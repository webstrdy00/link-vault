개인정보 안내

LinkFileBox의 개인정보 처리와 이용자 요청에 관한 검토본입니다.

LinkFileBox는 개인 개발자가 운영합니다.

제1조 (처리하는 정보와 목적)

  • 인증과 회원 승인: Google 로그인으로 전달되는 계정 식별정보·이메일과 회원 승인 상태를 계정 인증·접근 제어에 이용합니다. Google 계정 비밀번호를 앱에 입력받지 않습니다.
  • 개인 보관함: 사용자가 저장한 URL·제목·메모·분류와 확보한 메타정보를 저장·검색·분류에 이용합니다.
  • 직접 선택한 첨부: 항목당 이미지 한 장과 OCR 인식 결과를 저장·검색에 이용합니다. OCR은 기기에서 실행되지만 선택한 이미지와 결과는 서버에 업로드됩니다.
  • 기기 내 처리: 로그인 세션, 대기 중인 전송 요청과 임시 작성 내용, 보관함 캐시를 저장해 재접속과 재전송에 이용합니다.
  • 문의·삭제 처리: 문의자가 보낸 이메일과 요청 내용, 삭제 진행·재처리 기록을 요청 확인과 안전한 삭제에 이용합니다.

링크·메모·이미지에 불필요한 민감정보나 다른 사람의 개인정보를 포함하지 마세요. SNS의 좋아요나 비공개 계정 전체 자료를 자동 수집하는 기능은 없습니다.

제2조 (서비스 구성과 외부 처리)

  • Google: 로그인 인증, 선택한 이미지의 기기 내 ML Kit OCR.
  • 자체 운영 Supabase: 계정·DB·비공개 이미지 저장소와 API. 현재 AI Testbed 제공 NCP 서버를 사용합니다.
  • Cloudflare: 도메인·API 앞단의 네트워크 처리와 문의 메일 전달.
  • 메일 서비스: 전달된 문의 메일을 Gmail에서 확인합니다. 개인 수신 주소는 공개하지 않습니다.
  • GitHub Actions: 운영 자동화와 암호화 백업 아티팩트 보관.

이 목록은 구현 구성의 설명입니다. 각 서비스의 위탁 관계, 처리 국가·지역과 국외 이전 해당 여부·근거는 공개 전 확인 대상이며 이 검토본으로 법적 적합성을 보증하지 않습니다.

제3조 (보관과 삭제)

회원 자료는 서비스 제공에 이용하며 항목 삭제나 계정 탈퇴로 삭제를 요청할 수 있습니다. 앱의 삭제 안내는 운영 자료 정리 72시간 이내 목표, 운영 백업 최대 30일 순환 목표를 설명합니다. 이는 모든 사본의 즉시 삭제나 완료 시각을 보증하지 않습니다.

서버 로컬 백업은 최근 7개 스냅샷, GitHub 아티팩트는 30일 보관 설정으로 운영됩니다. 스냅샷 개수는 보관 일수와 같지 않습니다. 별도 복사한 백업까지 포함한 최종 보관·파기 정책은 확정해야 합니다. 복원 시 삭제 요청을 다시 적용하는 절차가 필요합니다.

삭제 작업·감사 기록은 활성 보관함 자료와 구분됩니다. 소스에서 확인한 정리 조건은 다음과 같으며, 실제 운영 작업의 실행과 완료까지 보증하는 기간은 아닙니다.

  • API 요청 기록은 7일, 요청 빈도 제한 기록은 1일이 지난 뒤 정리 작업의 삭제 대상이 됩니다.
  • 완료된 첨부 정리 기록은 완료 후 30일이 지난 뒤 삭제 대상이 됩니다.
  • 항목 삭제 표식과 완료된 계정 삭제 작업은 30일 경과뿐 아니라 해당 삭제 기록의 내보내기 확인이 필요합니다. 확인되지 않으면 더 오래 보관될 수 있습니다.
  • 삭제 원장에는 계정·항목·요청 식별자와 처리 시각 등이 남습니다. 연결된 삭제 표식·작업이 정리되고 내보내기가 확인되어야 삭제 대상이 됩니다. 진행 중인 계정 삭제 작업은 기간만으로 삭제하지 않습니다.

서버 로컬 백업의 최근 7개 유지도 성공한 백업의 순환 정리 기준입니다. 실패하거나 별도로 복사한 파일에 일괄 적용되는 최대 보관 기간이 아닙니다. 외부로 보관한 삭제 원장·백업, 문의 메일과 운영 로그의 최종 파기 정책은 공개 전에 확정해야 합니다.

확정한 복구본 보관 원칙: 새 검증 복구본을 확보하지 못한 경우 마지막 검증 복구본은 일반 순환 목표를 넘겨 예외 보존하고 운영 경고 대상으로 관리합니다. 예외 사유를 해소하고 대체 복구본을 검증한 뒤 기존 복구본을 정리하는 방향입니다. 복구본에 필요한 삭제 원장도 함께 보존해야 하며, 예외 사본으로 복원할 때도 삭제 요청을 다시 반영해야 합니다.

이 예외 보존·경고·해제 원칙은 승인된 정책이며 자동 집행 기능은 아직 구현·검증되지 않았습니다. 단순 파일 생성이나 암호화 성공만으로 복구 가능성이 검증됐다고 간주하지 않으며, 기존 백업을 일괄 삭제하지 않습니다.

제4조 (요청 방법)

앱에서 항목을 수정·삭제하거나 계정 탈퇴를 요청할 수 있습니다. 접근이 어려우면 문의 주소로 열람·정정·삭제 등 요청 내용을 보내주세요. 본인 확인 후 처리하며 비밀번호·인증 코드·토큰·신분증 사본을 이메일로 요구하지 않습니다.

이메일 접수만으로 요청이 처리되지는 않습니다. 앱 밖 탈퇴는 Google 재인증 기반 웹 요청과 인증된 진행 상태 조회 방식으로 구현하기로 결정했습니다. 이메일 발신 주소만으로 본인을 판단하지 않고 개인 이메일을 노출하는 회신도 사용하지 않습니다. 웹 기능은 아직 구현·검증되지 않았으며, 이 결정이 모든 개인정보 권리 요청의 처리 절차를 완성한 것은 아닙니다.
